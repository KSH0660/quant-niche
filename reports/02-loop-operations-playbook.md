# 02 — 루프 운영 플레이북 (하루종일 돌리면 뭐가 나오나)

> **이 문서가 답하는 것**: "Claude 루프 에이전트를 등록해 하루종일 돌리면 *실제로 무엇이 산출되는가*, 그리고 *어떻게 등록·운영하는가*."
>
> 설계: `reports/01-agent-harness-architecture.md` (4층 깔때기) · 절차: `research/RUNBOOK.md` · 코드: `src/quant_niche/` (Layer 0)

---

## 0. 한 줄 요약 (기대치 교정 먼저)

루프가 뱉는 건 **"수익"이 아니라 "의사결정 준비된 후보 + 추적 기록 + 기각 논리"**다.
실거래·사이징·최종 판정은 **운영자 몫**(자동화하지 않는다 — 헌법·RUNBOOK). 루프의 가치 =
*결정의 質을 높이는 정보* + *시간이 갈수록 복리로 쌓이는 forward 트랙레코드*.

> **"하루종일 Claude를 돌린다"는 표현 자체가 함정.** 24시간 깨어 있어야 하는 건 *공짜 코드(감시)*고,
> 비싼 Claude(판단 층)는 **신규/변화가 있을 때만** 깨운다. 이벤트는 희소하므로(아래 §4)
> 사이클의 ~90%는 "신규 없음, 스프레드 +0.1%"의 조용한 감시다. 진짜 산출은 가끔 터진다.

---

## 1. 루프가 산출하는 것 (주기별 결과물)

| 주기 | 산출물 | 예시 |
|---|---|---|
| **매일** | 신규 사건 숏리스트 + 추적 딜 스프레드 갱신 | `ACME 현금인수 $100, 현재 $96.2 → 스프레드 3.9%, 마감 90일, 연율 16%, HSR 대기` |
| **변화 시** | deal-break / 꼬리 경보 | `XYZ 딜: 공정위 2단계 진입 → 스프레드 3%→8% 급확대 ⚠️ 음의 왜도 경보` |
| **매주** | 백로그 아이디어 1~2건 판정 완료 | 010~013을 5-에이전트 파이프라인 통과 → `active/rejected/parked` |
| **누적** | 기각 묘지(다음 사냥의 필터) | `이 공개매수엔 단주 안분면제 조항 없음 → 기각` |
| **시간 누적** | 페이퍼 트랙레코드 (복리 자산) | `30일 추적 5건 중 4건 예상 수렴, 1건 break(−12%). 가정 슬리피지 0.3% vs 실제 0.5%` |
| **주 1회** | 종합 다이제스트 한 장 | 추적 N / 신규 M / 기각 K / 코어·위성 분류 / 배분 제안 |

### 하루치 산출 샘플 (이런 다이제스트가 매일 쌓인다)

```
[2026-06-03] quant-niche daily digest
신규 actionable: 1건
  • ACME (US, odd_lot_tender) SC TO-I — 더치옥션 $48~52, 단주 안분면제 O
    → 010 후보 적합. ideas/010 초안 생성, red-team 큐잉
추적 갱신: 4건
  • TGT2 합병 스프레드 3.9%→3.6% (수렴 정상)
  • XYZ 합병 스프레드 3%→8% ⚠️ 규제뉴스 — 꼬리 경보
기각: 1건 (CEF 청산일 미확정 → parked)
```

## 2. 한 사이클의 흐름 (무엇이 코드, 무엇이 Claude)

```
[cron, 매일] ──────────────────────────────── 비용 $0
  1. quant-niche collect --market all      (코드) 공시 폴링·diff
  2. ledger 갱신 + 추적 딜 스프레드 계산    (코드) 산술
        │  actionable(신규/변경) 있음?
        ▼  ── 없으면 여기서 종료(Claude 미소환) ──
[Claude 소환, actionable 있을 때만] ─────────── 비용: 소액
  3. 신규 사건 회의주의 1차 스키닝          (Sonnet) RUNBOOK 1·3단계
  4. 변화한 딜 재평가 / 꼬리 경보           (Sonnet) L3
  5. ideas/<id>.md·INDEX·digest 갱신        (Claude)
[주 1회]
  6. 백로그 1건 정식 파이프라인 통과        (Opus) RUNBOOK 5단계 풀세트
```

핵심: **Claude는 매 cron마다 부르지 않는다.** 코드가 "오늘 새로운 게 있나?"를 $0로 판정하고,
*있을 때만* Claude를 깨운다. 이것이 토큰=돈을 보존하는 방식.

## 3. 실제 등록 방법

### 3-1. 수동(권장 초기) — on-demand
흐름이 안정될 때까지 운영자가 직접 트리거. RUNBOOK 파이프라인을 메인 세션에서 호출.

```bash
uv run quant-niche collect --market all --days 7   # 신규/변경 숏리스트
# → actionable 있으면 그 건만 hunter→red-team→… 수동 진행
```

### 3-2. 자동 — `/loop` 또는 cron
흐름이 안정되면(아래 §5 전환 기준 충족) 1~2단계(수집·스키닝)만 자동화.

```
/loop 1d  "quant-niche collect --market all 실행 →
           신규/변화분만 회의주의 스키닝 →
           INDEX·대장 갱신 → daily digest 한 장 출력"
```

- cron은 매일 돌되, **Claude 소환은 actionable 있을 때만**.
- **판정·실거래 결정은 자동화하지 않는다** — 운영자 승인 유지(헌법).

### 3-3. 사전 요구사항
- **네트워크 allowlist**: EDGAR(efts.sec.gov), DART(opendart.fss.or.kr), Stooq. 샌드박스 기본 차단 → 운영자 환경 또는 allowlist 설정 필요.
- **DART_API_KEY**: 무료 발급(opendart.fss.or.kr) 후 환경변수. EDGAR는 키 불필요(식별 UA만).

## 4. 정직한 한계 (왜 "돈 복사기"가 아닌가)

1. **이벤트 희소성** — 미국 현금합병 주당 몇 건, 단주 공개매수 분기당 1~2건, CEF 청산은 더 드뭄(한국은 더 적음). 루프 산출은 *드물게* 터진다. "많이 돌린다 ≠ 많이 나온다."
2. **무료 데이터 비대칭** — 공시(EDGAR/DART)는 거의 실시간이라 사건성에 충분. 그러나 컨센서스·정밀 호가·ADV는 무료에서 약함 → 통계 아노말리(040 등)는 애초에 무료 재현이 병목. **루프가 잘 먹히는 건 1차 사냥터(사건성)지 통계 아노말리가 아니다.**
3. **음의 왜도** — 사건성 수렴은 평소 작게 벌고 가끔 크게 깨진다(deal-break). 루프의 절반은 *수익 발굴*이 아니라 *꼬리 감시*다. 그래서 극소 사이징·강분산·켈리 1/4 이하가 전제.
4. **추출 신뢰성** — Claude가 공시에서 뽑은 딜 조건(안분면제·조건·마감일)은 **사이징 전 원문 대조 필수**. 루프가 그럴듯한 잘못된 숏리스트를 만들 수 있다.
5. **돈은 운영자가 번다** — 루프는 후보·기록·논리까지. 실거래·사이징·판정은 사람이.

---

## 5. 복리로 쌓이는 진짜 자산

하루종일 돌려 *복리로 가치가 커지는* 세 가지 (이게 루프의 본질적 산출):

1. **이벤트 대장**(`data/ledger/events.jsonl`) — 빠짐없는 사건 커버리지 = 소액 개인의 실제 엣지.
2. **페이퍼 트랙레코드** — 가정 슬리피지·체결률 vs 실제. 운영자가 백테스트보다 신뢰하는 forward 증거(RUNBOOK ③④).
3. **기각 묘지**(`research/INDEX.md`) — 기각 논리 자체가 다음 사냥의 자동 제외 필터.

---

## 6. 자동화 전환 기준 (수동 → 루프)

수동 파이프라인이 다음을 만족할 때만 1~2단계를 `/loop`/cron으로 자동화한다(RUNBOOK):

- (a) 신규 이벤트를 안정적으로 포착하고,
- (b) 레드팀 기각률이 합리적이며,
- (c) 페이퍼 추적 결과가 메커니즘과 일치한다.

그 전까지는 수동 on-demand. 비싼 층(L2/L3 판단)과 실거래 결정은 **끝까지 사람 트리거**로 둔다.
