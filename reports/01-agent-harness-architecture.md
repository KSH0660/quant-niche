# 01 — 토큰-검약 에이전트 하네스 아키텍처

> **목적**: 사건성 기회(INDEX 1군)를 *라이브 추적*하되, **토큰=돈**이라는 제약 아래 LLM 호출을 환원 불가능한 판단에만 쓴다. 이 문서는 설계만 박제하며, 코드는 이후 점진 추가한다(현재 `strategies/`는 비어 있음).
>
> 헌법: `CLAUDE.md` · 운영절차: `research/RUNBOOK.md` · 사전지식: `reports/00-prior-art-synthesis.md`

> **⚠️ 2026-06 개정 (운영자 결정):** 아래 "토큰=돈" 강박은 **1차 제약에서 내려왔다.** 토큰 비용 하락·모델 지능 상승에 베팅하며, **판정 등 환원 불가능한 판단에는 Opus를 아끼지 않는다.** 다만 깔때기 구조 자체(변하지 않은 상태를 매번 재추론하지 않기)는 **여전히 유효한 엔지니어링**이다 — 절약이 *목적*이 아니라 중복 제거의 *부수효과*. 자동화 범위·실거래 게이트는 `CLAUDE.md` §운영 모델을 단일 진실로 따른다.

## 0. 설계 제1원칙

> **감시(watching)는 공짜 코드가 하고, 판단(judging)에는 가장 똑똑한 모델을 투입한다.**

24/7 루프에서 *"변하지 않은 상태를 매 사이클 다시 추론하는 것"*은 토큰이 싸져도 여전히 무의미한 중복이다. 따라서 전체를 **깔때기(funnel)**로 설계해, 결정론적 코드가 소방호스(전체 공시)를 물방울(진짜 새 사건)로 줄이고, **신규·변경된 판단점에만** LLM을 깨운다. 단 일단 깨운 판단에는 비용을 아끼지 않는다.

핵심 비대칭: 사건성 이벤트는 **희소**하다(미국 합병은 꾸준하나, 단주 공개매수 연 몇 건, CEF 청산은 더 희소). 그러므로 비싼 LLM을 상시 churn 하는 건 거의 다 순손실이다. 올바른 그림 = **상시 $0 수집 + 변화 트리거 시 소액 판단**.

## 1. 4층 깔때기

```
       소방호스 (전체 공시·가격)
            │
┌───────────▼────────────────────────────────────────────────┐
│ Layer 0  결정론적 수집기            LLM 토큰 $0   (cron 상시) │
│  · EDGAR/DART 폴러, yfinance/Stooq 가격                       │
│  · 상태해시 diff → 신규/변경만 통과                           │
│  · 스프레드·잔여일수·연율화수익·ADV·켈리 = 전부 코드          │
└───────────┬────────────────────────────────────────────────┘
            │ 신규/변경 후보만
┌───────────▼────────────────────────────────────────────────┐
│ Layer 1  싸구려 분류기              Haiku, 극소 토큰          │
│  · form-type/키워드 1차 결정론 프리필터 후 호출              │
│  · "현금합병/단주공개매수/CEF청산? + 핵심 5필드" 구조화 추출 │
│  · 1건=1호출, 큰 컨텍스트 비탑재                              │
└───────────┬────────────────────────────────────────────────┘
            │ 유효 신규 사건만 (주당 몇 건)
┌───────────▼────────────────────────────────────────────────┐
│ Layer 2  비싼 회의주의 추론        Sonnet→Opus, 이벤트 트리거│
│  · RUNBOOK 5-에이전트 풀세트(red-team deal-break·메커니즘·용량)│
│  · 시계가 아니라 이벤트가 깨움. ideas/<id>.md 작성·판정      │
└───────────┬────────────────────────────────────────────────┘
            │ 추적 채택 사건
┌───────────▼────────────────────────────────────────────────┐
│ Layer 3  변화-트리거 재추론        임계 돌파 시에만           │
│  · 코드가 매일 스프레드 계산($0)                             │
│  · 스프레드 블로우아웃/규제뉴스/상태변경 시에만 LLM 재가동   │
└─────────────────────────────────────────────────────────────┘
```

### 각 층 책임 경계 (무엇을 코드가, 무엇을 LLM이)

| 작업 | 담당 | 이유 |
|---|---|---|
| 공시 폴링·diff·중복제거 | 코드(L0) | 결정론, 토큰 0 |
| 스프레드·연율화·ADV·켈리 계산 | 코드(L0) | 산술은 LLM이 할 일 아님 |
| 폼타입/키워드 프리필터 | 코드(L0) | LLM 호출 전 잡음 제거 |
| 신규 공시 1차 분류·필드추출 | Haiku(L1) | 싸고 구조화 출력 적합 |
| deal-break·메커니즘·꼬리 판단 | Sonnet/Opus(L2) | 환원 불가능한 회의주의 판단 |
| 임계 돌파 재판단 | Sonnet/Opus(L3) | 상태변화 시에만 |

## 2. 토큰 규율 전술

| 누수 지점 | 대책 |
|---|---|
| 헌법·priors 매 호출 재전송 | **prompt caching** — 고정 컨텍스트(CLAUDE.md, priors)는 캐시 |
| 에이전트가 레포 전체 읽음 | 대상 `ideas/<id>.md` + compact 상태파일만 (RUNBOOK 기설계) |
| 같은 사건 반복 추론 | **idempotency store**(`seen` 키) — 판정한 건 재추론 금지 |
| 원시 공시 매번 재파싱 | **머신 가독 상태파일**(아래 §3) → LLM은 작은 구조화 요약만 읽음 |
| 모든 일에 Opus | **모델 티어링**: 분류=Haiku, 판단=Sonnet, 최종 회의주의=Opus |
| 24/7 churn | 이벤트 희소 → daily cron + event-driven. 상시 churn 금지 |

**토큰 예산 사고법**: "이 호출이 *새 정보에 대한 판단*인가, *아는 걸 다시 말하는 것*인가?" 후자면 코드로 내리거나 캐시/스킵.

## 3. 상태 스키마 (단일 진실 — 양 시장 공통)

LLM이 원시 공시를 매번 재파싱하지 않도록, 결정론 층이 채우는 **머신 가독 대장**을 둔다. (`data/`는 git 제외이므로 이벤트 대장은 `data/ledger/`에 캐시, 판정·논리는 `research/ideas/`에 영속.)

`data/ledger/events.jsonl` (Layer 0~1 산출, 한 줄 = 한 사건):

```jsonc
{
  "event_id": "us-edgar-SCTOI-0001234-2026",   // 결정론적 키(중복제거)
  "market": "US|KR",
  "source": "EDGAR|DART",
  "form_type": "SC TO-I|DEFM14A|S-4|N-2|공개매수신고서|...",
  "kind": "merger_cash|odd_lot_tender|cef_liquidation|forced_burn|null",
  "ticker": "...", "filed_at": "2026-06-03",
  "deal_price": 0.0, "deadline": "2026-09-30",
  "odd_lot_provision": true,                    // 단주 안분면제 조항 유무
  "spread_pct": null, "annualized": null,       // L0가 가격 붙여 계산
  "state_hash": "sha256...",                    // 변경 감지
  "classified_by": "haiku|deterministic",
  "status": "new|screened|tracked|rejected|closed",
  "idea_file": "research/ideas/011-....md"      // L2 진입 시 연결
}
```

원칙: **사실(가격·필드)은 코드가 ledger에, 판단(생존/기각 논리)은 LLM이 `ideas/`에**. 둘을 섞지 않는다.

## 4. Cadence (스케줄)

| 주기 | 작업 | 비용 |
|---|---|---|
| **상시/일 1회(종가)** | L0 수집기: 신규 공시 diff + 추적 딜 스프레드 스냅샷 | $0 |
| **신규 감지 시** | L1 분류 → 유효 시 L2 회의주의 깨움 | 소액·event-driven |
| **임계 돌파 시** | L3 재판단(스프레드 블로우아웃·규제뉴스) | 소액·state-driven |
| **주 1회** | 백로그 1건 파이프라인 갈기(유한 작업) | 중간 |
| **분기 1회** | active 아이디어 메커니즘 문헌 점검 | 소액 |

스케줄링은 `/loop` 스킬 또는 SessionStart hook + cron. **수집기(L0)는 에이전트 없이 cron으로**, LLM은 수집기가 신규 후보를 뱉을 때만 소환(큐/웹훅 스타일).

## 5. 복리로 쌓이는 자산 (이 하네스의 진짜 산출물)

돈복사기가 아니다. 하루종일 돌려 **복리로 가치가 커지는 건 세 가지**다:

1. **이벤트 대장**(`data/ledger/`) — 빠짐없는 사건 커버리지 = 소액 개인의 실제 엣지
2. **페이퍼 트랙레코드** — 가정 슬리피지·체결률 vs 실제 대조(RUNBOOK ③④) = 운영자가 백테스트보다 신뢰하는 forward 증거
3. **기각 묘지**(`research/INDEX.md`) — 기각 논리 자체가 다음 단서

## 6. 정직성 가드레일 (헌법 준수)

- LLM은 공시 *판단*만 한다. **공시에서 추출한 딜 조건(안분면제·조건·마감일)은 사이징 전 반드시 원문 대조** — 에이전트의 오파싱이 그럴듯한 잘못된 숏리스트를 만들 수 있다.
- **무료 데이터 한계의 비대칭**: EDGAR/DART *공시*는 거의 실시간(사건성에 충분). 그러나 컨센서스·정밀호가·ADV 세분화는 무료에서 약함 → 040(PEAD)류는 애초에 무료 재현이 병목. 루프가 잘 먹히는 건 **1차 사냥터(사건성)**이지 통계 아노말리가 아니다.
- **판정은 자동화한다**(Opus). **실거래 주문 집행만** `CLAUDE.md` §운영 모델의 게이트 스위치를 따른다 — 기본 `HUMAN_APPROVAL`(운영자 승인이 주문의 유일 트리거), 운영자가 `FULL_AUTO`로 토글 가능. 토큰/지능으로 사라지지 않는 *비가역성·음의 왜도* 때문에 이 한 가지만 의식적 선택으로 남긴다.

## 7. 다음 단계 (코드 단계 진입 시)

운영자 선택: 양 시장(EDGAR + DART) Layer 0부터.

1. `data/ledger/` 스키마(§3) 확정 + `events.jsonl` 초기화
2. **EDGAR 폴러**: full-text search/RSS로 `SC TO-I/TO-T`·`DEFM14A`·`S-4`·`N-2` 신규 diff
3. **DART 폴러**: OpenAPI로 공개매수·합병·자사주 의무소각 신규 diff
4. yfinance/Stooq 가격 붙여 스프레드·연율화 계산(코드)
5. L1 Haiku 분류기 배선 → 유효 사건만 L2(RUNBOOK 5-에이전트)로
6. `/loop`/cron 스케줄로 L0 상시화

> 이 순서는 "자동화 우선 — 살아있는 로컬 세션의 `/loop /quant-daily`가 L0 수집(`make collect`) → 세션(Opus)이 신규 actionable마다 에이전트 체인을 직접 소환 → Opus 판정 → 최상단 브리프 갱신"(RUNBOOK 현행)과 정합. L2/L3도 이벤트 트리거로 자동 소환되며, 사람 게이트는 실거래 주문 집행 한 곳에만 둔다(게이트 스위치).
